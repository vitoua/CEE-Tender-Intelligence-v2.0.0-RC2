# GOODRAM Tender Intelligence 2.0.0-RC2

Повний самостійний rebuild. Не патч, не overlay. Усі вихідні файли й конфігурація розгортання включені. Не потрібно накладати попередні версії.

## Що реалізовано
- Новий navy/mint дизайн, адаптивні desktop/mobile сторінки.
- Вибір країн і джерел, дата публікації, мінімальна сума EUR.
- Прогрес збору, статуси та пояснення покриття кожного джерела.
- SQLite: тендери, профілі фільтрів, історія запусків, кеш перекладу.
- Помилка джерела не стирає попередній результат: непідтверджені записи позначаються stale й мають окремий список.
- Окремі стани: активні, на перевірку, планування, закриті, прострочені.
- Редактори CPV/ключових слів із валідацією; зміни застосовуються після наступного збору.
- Фільтри списку, сторінки по 50 записів, картка тендера, оригінал/переклад.
- Excel, CSV, JSON: експорт поточного фільтра. Excel/CSV захищені від формул у зовнішньому тексті.
- Аналітика: KPI, діаграми за країнами, джерелами й датою публікації; фільтри.
- Основна навігація UA/PL/EN/ES. Частина технічних повідомлень залишається англійською: повна локалізація НЕ завершена.
- MyMemory без ключа, Azure, LibreTranslate; одиничний/груповий переклад, тест, кеш, квота та cooldown після 429.
- Захист write-операцій ADMIN_TOKEN, секрети не передаються в URL Apify.

## Render: заміна попереднього проєкту
1. Збережіть резервну копію поточного репозиторію. Замініть код ВМІСТОМ цього архіву в корені. Старий build_hotfix.py не потрібен. Не залишайте старий Dockerfile чи overlay.
2. Runtime: Docker. Root Directory: порожньо. Dockerfile Path: ./Dockerfile. Docker Build Context: . . Docker Command: порожньо.
3. Environment: задайте ADMIN_TOKEN (довге випадкове значення). Не надсилайте його в чат. Якщо створюєте сервіс через render.yaml, токен генерується Blueprint-конфігурацією; для існуючого сервісу задайте вручну.
4. Після deploy відкрийте /health: version 2.0.0-RC2, build_id v200-native-rc2.
5. Відкрийте Settings і введіть ADMIN_TOKEN. Він зберігається тільки в sessionStorage поточної вкладки браузера. Read-сторінки публічні, це не повна система користувачів.
6. Спочатку тестуйте одне джерело й одну країну. Статус partial означає обмежений збір, а не повне покриття. Порожній список не доводить відсутність тендерів.

## Зберігання
SQLite зберігає дані між перезапусками процесу на тому самому файловому диску. Для збереження між redeploy потрібен persistent volume й DATA_DIR на ньому. Render Free з ефемерним диском не гарантує збереження. JSON-профілі за замовчуванням завжди читаються з data/profiles.json, зміни з UI зберігаються в SQLite.
Стару in-memory базу v1.4.4 автоматично не імпортовано. Кеші старої версії також не мігруються. Початкова база порожня, демонстраційних тендерів немає.

## Важливі обмеження
- Це RC2, не твердження «всі проблеми усунено». Чотири національні адаптери тепер мають власний код збору з порталів і НЕ викликають TED. Це native beta, а не підтвердження працездатності на всіх поточних live-схемах.
- Усі джерела виконуються послідовно. Таймаут 180 секунд на джерело; при timeout попередні дані зберігаються stale. Поточні часткові дані конектора при timeout можуть бути втрачені.
- Дедлайни з timezone приводяться до UTC. Для локальних дат без offset застосовується зона порталу там, де вона явно задана. Date-only deadline не доводить точний час; такий запис іде на перевірку.
- Для multi-lot TED зберігається найраніший дедлайн із приміткою; повна модель лотів не реалізована.
- Сума не конвертується автоматично. Якщо мінімум EUR > 0, відома EUR-сума нижче порогу відхиляється; невідома/інша валюта зберігається review з приміткою.
- Точний duplicate key усередині джерела усувається. Cross-source fuzzy dedup не реалізовано: аналітика рахує записи, не унікальні процедури між порталами.
- Stale-записи не показуються як підтверджені активні. Їх видно у власному списку або All.
- Вільний переклад обмежено локальним бюджетом 5000 символів/день; зовнішній провайдер може мати інші ліміти. Квота не обходиться. Кеш і квота в SQLite; cooldown у пам'яті.
- TED multilingual: виберіть справжню мову джерела вручну. Для нових native-адаптерів мовою порталу є sk/lt/hu/et; для TED мову потрібно вибрати вручну.
- Перекладається до 6000 символів опису; отриманий оригінальний опис залишається в картці. Масовий переклад до 20 записів за дію.
- Немає автоматичного розкладу, багатокористувацького RBAC, авторизації читання чи multi-worker job coordination. Docker запускає один worker.
- BZP: HTML обрізається до 60000 символів для парсингу, опис до 16000; це не повний текст вкладень.
- Зовнішні документи/вкладення не завантажуються автоматично; відображаються посилання, коли вони є у джерелі.

## EKAP
Задайте APIFY_API_TOKEN, APIFY_ACTOR_ID, APIFY_INPUT_JSON. Actor може бути платним. Input JSON береться з вашого робочого Actor. Очікувані вихідні поля: id або tenderNo; title або name; buyer; publicationDate; deadline; value; currency; url або link; description; cpv. Невідомі поля не домислюються. Раніше оприлюднені токени замініть.

## Native-конектори RC2: доступ і ресурси
Dockerfile встановлює Playwright і Chromium з системними залежностями. Це збільшує образ і витрати пам'яті. NATIVE_BROWSER=1 за замовчуванням. Для локального запуску після requirements виконайте: python -m playwright install --with-deps chromium . CHROMIUM_EXECUTABLE задається лише для нестандартного шляху браузера.
NATIVE_BROWSER=0 вимикає браузер: Естонія повідомить browser_required; Литва/Угорщина можуть повернути обмежений HTML-результат із browser_warning. Жодної автоматичної підміни TED немає.
Мінімальний тариф Render Free не перевірено з Chromium; відсутність перезапусків від нестачі RAM не гарантована. Не обіцяємо повне покриття періоду: latest-list може не дійти до потрібних релевантних закупівель через ліміти. Невдала пагінація позначається явно. Для SK/LT немає перевіреного server-side пошуку за ключовими словами: фільтрація локальна після bounded scan.
Прямі HTTP-запити з середовища підготовки повернули 403 для всіх чотирьох порталів. Це не доводить блокування на Render. Web-інструмент прочитав офіційні сторінки SK/LT/HU, але не надав raw HTML для end-to-end прогону. Estonia DOM-label mapping перевірений лише на синтетичних fixtures. Не називайте ці тести live-підтвердженням.

## Локальна перевірка
python -m pip install -r requirements.txt
PYTHONPATH=. python tests/test_app.py
PYTHONPATH=. python tests/test_native.py
PYTHONPATH=.:tests python tests/test_native_browser.py
python -m uvicorn app.main:app --host 0.0.0.0 --port 10000 --workers 1

У Windows PowerShell перед тестом: $env:PYTHONPATH='.' . Змінні середовища задаються окремо; .env.example є лише прикладом, автоматичного читання .env немає.
